### 1. Governing differential equation (the “physics” block)

\[
\boxed{ \; \ddot y(t) + a\,\dot y(t) + b\,y(t) + c\,y^{3}(t) = g\,u(t) \;}
\]

*State vector* \(x(t)=\begin{bmatrix}y(t)\\ v(t)\end{bmatrix}\) with \(v=\dot y\).  
The unknown acceleration \(\ddot y\) will be supplied by a neural network \(\mathcal N_\theta\).

\[
\dot x(t)=
\begin{bmatrix}
v(t)\\
\mathcal N_\theta\!\big( \underbrace{[y(t),\,v(t),\,u(t)]}_{\text{raw inputs}}\big)
\end{bmatrix}
\equiv f_\theta(x(t),u(t))
\]

The network is trained to make the integrated trajectory match the measured output while the parameters \(a,b,c,g\) are *fixed* to the physical constants we will learn as trainable scalars (optional – can be learned jointly).

---

### 2. Neural‑network architecture

| Component | Choice & Rationale |
|-----------|--------------------|
| **Raw inputs** | \([y,\,v,\,u]\) (3‑dim) |
| **Input scaling** | Standard‑score each channel using the mean & std of the *training* slice (3072 samples). Store the scalers for inference. |
| **Depth** | 4 hidden layers – enough capacity but still cheap for CPU. |
| **Width** | 64 neurons per hidden layer – balances expressivity and speed. |
| **Activation** | `tanh` (smooth, bounded, good for dynamics). |
| **Output** | Single scalar \(\hat a = \mathcal N_\theta(\cdot)\) representing \(\ddot y\). No activation (linear). |
| **Output scaling** | After training, multiply the raw output by a factor equal to the standard deviation of the *target* acceleration (computed from finite‑difference of the training y). This keeps the network’s magnitude in the same range as the physics term. |
| **Parameter handling** | Optional trainable scalars \(\{a,b,c,g\}\) initialized from rough physical estimates (e.g., from linear fit) and constrained to stay positive via a soft‑plus transform. |

Total trainable parameters ≈ 4 × (64 × 64) + biases ≈ 16 k – trivial for a 5‑min CPU run.

---

### 3. State integration – RK4

Given a time step \(\Delta t = 1/fs\) (≈ 0.001637 s), the RK4 update for one step from \(t_n\) to \(t_{n+1}\) is:

```
k1 = fθ(x_n, u_n)
k2 = fθ(x_n + Δt/2 * k1, u_{n+½})
k3 = fθ(x_n + Δt/2 * k2, u_{n+½})
k4 = fθ(x_n + Δt   * k3, u_{n+1})
x_{n+1} = x_n + Δt/6 * (k1 + 2*k2 + 2*k3 + k4)
```

*Note*: `u_{n+½}` is obtained by linear interpolation of the input signal (or simply use the nearest sample – the error is negligible at this sampling rate).

The integrator will be vectorised over the whole rollout to stay within the 5‑min budget.

---

### 4. Training objective & strategy

**Loss** (per rollout segment of length \(L\)):

\[
\mathcal L = \frac{1}{L}\sum_{i=1}^{L}\bigl( y_i^{\text{pred}} - y_i^{\text{meas}} \bigr)^2
          + \lambda_{\text{reg}}\| \theta \|_2^2
\]

*Why a rollout?*  
Training on short windows (e.g., 128‑step windows) prevents the network from collapsing to the trivial zero‑acceleration solution, because the RK4 integration forces consistency over several steps.

**Hyper‑parameters**

| Item | Value / Reason |
|------|----------------|
| Optimizer | Adam |
| Learning rate | \(1\times10^{-3}\) (start) → cosine‑anneal to \(1\times10^{-5}\) over the whole schedule |
| Batch size | 32 windows (randomly sampled from the 3072‑sample training segment) |
| Window / rollout length \(L\) | 128 steps (≈ 0.21 s) – long enough to capture the nonlinear dynamics, short enough to keep gradients stable |
| Total steps | 3000 updates (≈ 1 epoch ≈ 10 s, total < 2 min) – we can overshoot to 5000 if time permits |
| Gradient clipping | 1.0 (norm) to avoid exploding gradients |
| Regularisation λ | \(1\times10^{-6}\) (tiny, just to keep weights bounded) |
| Early‑stop | monitor validation RMSE on the last 256 samples of the training slice; stop if no improvement for 500 steps |

**Avoiding degenerate fit**  

1. **Non‑zero initialization** – initialise the final linear layer bias to a small value (e.g., 0.1) so the network initially predicts a modest acceleration.  
2. **Physics‑aware scaling** – the output scaling described above keeps the network’s magnitude comparable to the true acceleration.  
3. **Rollout loss** – by integrating over > 1 step the network cannot simply output zero; the error accumulates quickly if dynamics are wrong.  
4. **Optional parameter learning** – learning \(a,b,c,g\) jointly gives the optimizer extra degrees of freedom to fit the linear part, leaving the MLP to capture the cubic term.
